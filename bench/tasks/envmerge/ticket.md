Build `envmerge`, this repository's console script, which merges dotenv files for a deployment:

    envmerge <schema.toml> --out <file.env> <base.env> [<overlay.env> ...] [--allow-unknown]

The schema is TOML: one `[vars.<NAME>]` table per variable, with `type` (one of `string`, `int`,
`bool`, `port`, `url`, `enum`), optional `required` (bool, default false), optional `default`
(a string), and for `enum` a `values` list of strings. A dotenv file has `NAME=value` lines; blank
lines and `#` comment lines are ignored; an optional `export ` prefix is allowed; a value may be
unquoted (a trailing ` # comment` is stripped and surrounding whitespace trimmed), single-quoted
(taken literally) or double-quoted (with `\n`, `\t`, `\\`, `\"` and `\$` escapes). Names match
`[A-Za-z_][A-Za-z0-9_]*`. Later files override earlier ones.

Type rules: `int` is an optional sign and digits; `bool` is true/false/yes/no/on/off/1/0 in any
case; `port` is an integer from 1 to 65535; `url` has a scheme and a host; `enum` must be one of
`values`; `string` is anything.

Merge the files in order, apply defaults for variables that are missing, then check: each problem
is `ERROR <NAME>: ...`, sorted: a required variable that is missing and has no default; a value of
the wrong type; a variable that is not in the schema, unless `--allow-unknown`, in which case it
is kept and reported as `WARN <NAME>: not in the schema`. A line that cannot be parsed is
`ERROR <file>:<line number>: ...`. A schema that cannot be read or is malformed is
`ERROR schema: ...`, and nothing else is checked. Print the ERROR and WARN lines sorted together.
If there is any ERROR, do not write <out> (an existing <out> is left exactly as it was) and exit 1.
Otherwise write <out>: a first line `# generated by envmerge from <the input file names, comma
separated, in order>`, then `NAME=value` lines sorted by name, every value double-quoted using the
escapes above; print `MERGED <number of variables> from <number of files> files` and exit 0.
Never leave a partial <out>: write it whole or not at all. Any other failure is one line on stderr
and a non-zero exit, never a traceback. Write tests; `uv run pytest -q` and `uv run ruff check .`
must pass.
