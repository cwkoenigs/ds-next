ds-next · terminal design system · v1 draft

One rail, three voices,
nothing moves that didn't change.

A design system for the ds-next terminal: colour roles, a glyph vocabulary, an indent grid, every message type, and three directions for the screens — 1a Rail, 1b Ledger, 1c Plate, shown first. It is written for the two things you said feel off — UI movement (what appears, where, and what stays still) and information navigation (finding the thing you need in a long session). Baseline screens are in ds-next Baseline; the tokens ship as ui_style.py.

Assumptions
StackRich + prompt_toolkit stay; no full-screen TUI. Everything here is printable lines. ColourTruecolor, derived from the Industry steel ramp; falls back to ANSI-16 when the terminal can't. WidthDesigned at 80 columns, degrades to 60; mocks are 80 wide. ReferenceClaude Code's rail and collapse behaviour; Cortex Code's quiet chrome; Hermes' glyph economy.
1Three directionsSame flow each time: banner → /new form → the turn → an approval → /status. All three use sections 2–6; they differ in how the screen is organised.
1aRail — Claude-Code lineage. One vertical line per turn carries every event; turns are numbered so you can refer back. Movement: only the rail tip is live.

2Principles

One rail

Everything the agent does in a turn hangs off a single vertical line in column 1. Your eye finds the rail, then reads sideways. Local commands have no rail: they are instant and flat.

Three voices

You (›, text colour), the agent (●, accent), the machine (→ │ ⎿, muted). Outcome glyphs ✓ ⚠ ✗ are the only other colours on screen.

Nothing moves that didn't change

One live line at a time — the status line at the rail's tip. It is reused, never stacked. Labels, gutters and the toolbar never shift; only content streams.

Everything is addressable

Turns are numbered, tool results collapse to one line with a count and a key to open them, standards and files are always written as ids you can type back.

A frame means "needs you"

Boxes are rare and they always mean input: the form, an approval, a question. Output is never boxed. The banner is the one decorative exception, shown once.

Same grammar without the model

ds-next reconcile in CI prints the same glyphs and columns as /status, minus colour when not a TTY. One renderer, two outputs.

3Colour roles

Twelve roles, two themes, one source: the Industry steel ramp (--color-accent-*) and neutral ramp. On dark the accent steps up to accent-400, on light it steps down to accent-700, so paragraph text in the accent stays above 4.5:1. ok / warn / err are generated in OKLCH at the same lightness as the accent so they weigh the same — the one place the CLI needs colour the Industry palette doesn't carry. Each role has a fixed ANSI-16 fallback.

4Glyph vocabulary

Eleven glyphs. Each means one thing, in one colour, in one column. The baseline used ◆ for both "agent says" and "widget title" and │ for both output and status lines; these are split. All glyphs are in Menlo, SF Mono, JetBrains Mono, Cascadia and the DejaVu set, so VS Code's terminal draws them without a Nerd Font.

5Grid, indent and rhythm
5aThe 80-column grid every screen sits on
col 1 3 16 80
│ │ │ │
› you type here
● agent text starts at col 3 and wraps to col 3
│ → tool(arg) also at col 3
│ ⎿ results at col 5, under the tool's name
╰ footer at col 3
label │ form values and table cells start at col 16
purpose *│ the label column is 12 + mark + space = col 3..15
│ │ │ │
rhythm one blank line between turns · none inside a turn · two before a frame

Two indents only. Column 3 for everything that is said or run; column 5 for what came back. The baseline's 2-space, 3-space and 17-column indents collapse into these.

Label column = 12. Forms, the draft summary, /status detail, and the reconcile subcommand share it, so a value is always in the same place.

Rhythm. Blank lines separate turns, never messages within a turn — the rail does that. Frames get a blank line above and below so they read as objects.

Width. Lines wrap at the terminal width minus 2. Nothing is truncated except the first line of a result (col 5 to the edge), and that is marked with ┄.

7Motion

One live line

The status line (◐ Running Bash · 4s) is the only line that redraws. It sits at the rail tip and is replaced by the next event in place — never printed above the output as the baseline spinner is.

Append, don't reflow

Nothing printed is reprinted. The toolbar is the only persistent region and it changes at most once per prompt. Widgets erase themselves whole; their result is re-printed as a static line (✓ python-cli v1).

Fold, then open

Results print their first line plus ┄ N more lines · ctrl-o. ctrl-o expands the last fold in place (Claude Code's habit); /last prints the full result of the last tool call.

Spinner tempo

◐◓◑◒ at 8 fps, elapsed seconds update once a second, the step name changes only on a new message. Three different cadences, so the eye reads "alive", "how long", "what" separately.
